# Laravel CI/CD Lab 10

## Описание проекта

Проект представляет собой веб-приложение на Laravel для управления транспортной сетью. В приложении реализованы основные сущности транспортной системы, работа с пользователями, маршрутами, станциями, транспортом и административными разделами.

Для проекта настроен CI/CD pipeline, который автоматически запускается при изменениях в основных ветках репозитория. Pipeline проверяет корректность кода, запускает тесты, контролирует минимальное покрытие тестами, выполняет статический анализ и проверяет форматирование кода.

## Используемые ветки

В проекте используются долгоживущие ветки:

* `dev` — ветка для разработки;
* `qa` — ветка для тестирования;
* `main` — основная production-ветка.

Для каждой ветки используется отдельная конфигурация окружения:

* `dev` использует `.env.dev`;
* `qa` использует `.env.uat`;
* `main` использует `.env.prod`;
* для выполнения pipeline используется `.env.ci`.

## Описание CI/CD pipeline

Pipeline настроен с помощью GitHub Actions и находится в файле:

```text
.github/workflows/ci.yml
```

Pipeline запускается при `push` и `pull_request` в основные ветки проекта.

Основные этапы pipeline:

### 1. Запуск тестов

На первом этапе выполняются Laravel-тесты. Также проверяется покрытие кода тестами. Минимальный допустимый уровень покрытия установлен на 50%.

Если один из тестов завершается с ошибкой или покрытие ниже 50%, pipeline завершается неуспешно.

### 2. Статический анализ кода

На втором этапе выполняется статический анализ кода с помощью Larastan/PHPStan.

Этот этап позволяет находить ошибки типов, неправильные вызовы методов, проблемы в структуре кода и другие потенциальные ошибки до запуска приложения.

Если PHPStan находит ошибку, pipeline завершается неуспешно.

### 3. Проверка форматирования кода

На третьем этапе выполняется проверка стиля кода с помощью Laravel Pint.

Pint запускается в test-режиме, поэтому он только проверяет форматирование и не исправляет файлы автоматически. Если находятся нарушения стиля кода, pipeline завершается неуспешно.

### 4. Симуляция деплоя

После успешного прохождения тестов, статического анализа и проверки форматирования выполняется симуляция деплоя.

В зависимости от ветки pipeline выбирает соответствующий `.env`-файл:

```text
dev  -> .env.dev
qa   -> .env.uat
main -> .env.prod
```

На этапе симуляции деплоя соответствующий файл окружения копируется как `.env`, после чего в лог выводится сообщение о деплое в выбранную среду.

Для production-ветки `main` используется отдельная среда `production`, для которой может быть настроено ручное подтверждение перед выполнением production deploy job.

## Используемые инструменты

В pipeline используются следующие инструменты:

* GitHub Actions — автоматизация CI/CD;
* PHPUnit / Laravel Test Runner — запуск тестов Laravel;
* Xdebug — подсчёт покрытия кода тестами;
* Larastan / PHPStan — статический анализ PHP-кода;
* Laravel Pint — проверка форматирования и стиля кода;
* Composer — установка PHP-зависимостей;
* SQLite — база данных для CI-окружения.

## Файлы окружения

В проекте используются отдельные файлы окружения:

```text
.env.dev
.env.uat
.env.prod
.env.ci
```

Основной файл `.env` не добавляется в репозиторий и находится в `.gitignore`.

Файл `.env.ci` используется только для запуска pipeline. Он настроен на использование SQLite, чтобы проверки могли выполняться в GitHub Actions без отдельной настройки внешней базы данных.

## Результат работы pipeline

Pipeline считается успешным, если:

* все тесты проходят успешно;
* покрытие кода тестами не ниже 50%;
* статический анализ не находит ошибок;
* Laravel Pint не находит нарушений форматирования;
* этап симуляции деплоя выполняется успешно.

Если хотя бы один из обязательных этапов завершается с ошибкой, весь pipeline получает статус `failed`.
